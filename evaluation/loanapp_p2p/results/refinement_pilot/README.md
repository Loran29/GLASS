## Findings to keep in mind

- Feedback gate: the UI's keyword check on feedback (`validate_refinement_scope`) would block 7/9 cases (LoanApp_G1G2_rep1, LoanApp_G2G3_rep1, Procure2Pay_G2_rep1, Procure2Pay_G3_rep1, Procure2Pay_G1G2_rep1, Procure2Pay_G1G3_rep1, Procure2Pay_G2G3_rep1); the UI would show an error and not refine.
- Accepted KPIs dropped by the model (2), although the prompt asks to keep accepted KPIs unchanged and to return exactly total_kpis KPIs; GLASS does not enforce this in code:
  - LoanApp_G2G3_rep1: "Average Wait Time Before Loan Offer Approval"
  - Procure2Pay_G1G3_rep1: "Average Duration of Settling Disputes with Suppliers"
- Soft credit: in Procure2Pay_G3_rep1, "Purchasing Agent Workload by Time of Day" (category utilization, measurable_as Resource Utilization) counts towards Purchasing Agent Utilization under both rule sets, but its formula `COUNT('Create Request for Quotation Requester Manager') grouped by event_hour_of_day` counts activity occurrences per hour; it is not a utilization measure.
- `outcome` (lenient scoring): reached_without_refinement = all expected KPIs already in the first proposal; reached_after_1_round = all present after round 1; not_reached_after_1_round otherwise.

## Method notes

- First proposal = `result` of the `stage1_results_normalised/` record whose
  `normalisation.source_file_sha256` equals the SHA-256 of the `stage1_results/` source file (same LLM
  answer, post-processed by the GLASS version used here). Before and after are scored under the same code.
- Undecided KPIs are treated as accepted: the UI enables "Refine KPIs" only when no KPI is pending.
  Each record lists them under `decisions.undecided_treated_as_accepted`.
- Feedback is passed straight to the prompt. The UI's keyword check on feedback
  (`validate_refinement_scope`) is recorded per case (`feedback_scope_gate_passed`), not enforced;
  it would block: LoanApp_G1G2_rep1, LoanApp_G2G3_rep1, Procure2Pay_G2_rep1, Procure2Pay_G3_rep1, Procure2Pay_G1G2_rep1, Procure2Pay_G1G3_rep1, Procure2Pay_G2G3_rep1.
- Expected KPIs are scored with the batch's rule sets; `<role> Utilization` is scored as
  `Resource Utilization` (the lenient rule does not check the role).
- `accepted_unchanged`: every accepted KPI is still present with identical name and suggested_formula.
